# UX Recon — reference storefront vs. template

Date: 2026-11-05
Live reference: <https://politesocietyshop.com>
Clone: <http://localhost:3000>
Viewports: 1440 × 1000 and 390 × 844
Method: Playwright MCP browser automation, `browser_evaluate` computed-style/DOM measurements, screenshots, console and network inspection. No application code was changed.

Legend: **Observed** means measured in the browser on this run. **Assumption** means an inference that was not proven on this run.

Environment notes:

- The live site geo-localized to India on this run: INR currency, ₹ prices. The clone uses USD. Price values are therefore not directly comparable. **Assumption:** this is IP localization, not a clone defect.
- The clone screenshots include the Next.js development “N” badge at bottom-left. That is the dev overlay, not storefront design.
- Live popup/newsletter state was already suppressed by a previous `ps_popup_seen` localStorage entry. It was cleared to observe the popup, then dismissed normally.

## Top findings

1. **The clone’s mobile collection page is horizontally broken.** At 390 px, `/collections/all` has `document.scrollWidth = 579` while `innerWidth = 390`. The grid is 538.8 px wide with 267.9 px columns, the second card is cut off, and the sort control sits at x = 473.6, completely off-screen. The chip scroller reports `scrollWidth = 747` / `clientWidth = 579`; an ancestor with `min-width: auto` widens the whole page instead of clipping the scroller. **Observed.**
2. **Clone typography is consistently lighter and looser than live.** Nav links, card titles, section headings, and PDP H1 use weight 300 instead of 400; desktop “OUR PICKS” is 16 px instead of 18 px; nav line-height is 21 px instead of 18 px; PDP H1 adds 1.1 px tracking that live does not have. The layout looks close at a glance, but the editorial hierarchy reads thinner. **Observed.**
3. **The clone PDP lost two high-value live patterns.** Live has a transparent header over a full-bleed gallery and visual colour swatches; the clone uses a solid header that pushes the gallery down, renders colours as text links, performs a client-side route change for every option, and omits “BUY IT NOW.” **Observed.**
4. **The clone cards are missing quick actions.** Live exposes a 28 × 28 quick-view button on hover (`0.25 s`, same easing family as the image swap). The clone only has a wishlist button; there is no quick view or quick add. The clone does add a `1.03` image scale on hover that live does not have. **Observed.**
5. **Discovery surfaces are shallower than live.** Live filter has product type, colour, and fabric facets; clone filter has only price and availability. Live search shows larger product rows, a collections group, and a result count; clone search shows four compact suggestions and “VIEW ALL RESULTS,” with a duplicated “SEARCH” label. **Observed.**
6. **Popup behaviour matches, presentation does not.** Both appear after 5 s and suppress for 30 days via localStorage. Live’s card is 720 × 271 on desktop / 350 × 258 on mobile with a 26 × 26 close target; clone’s is 448 × 239 / 358 × 239 with a 16 × 16 close target. **Observed.**
7. **One real clone console error.** React reports `Received false for a non-boolean attribute compact` from the PDP option picker: `compact` is accepted by `OptionPicker` but not destructured, so it is spread onto the DOM `div`. **Observed; source location inspected.**

Additional observations:

- Live’s desktop collection starts with “Alphabetically, A-Z”; clone starts with “Featured.” This changes the first viewport of products and may explain part of the product-order mismatch. **Observed.**
- Live’s collection default chip row is a product-type facet list; clone’s is a collection shortcut list. The clone collapses live’s 16 chips into 8 collection names, losing product-type drill-down at the top of the page. **Observed.**
- The clone mobile card layout is clipped, but its cards are otherwise the same size as the desktop cards (267.9 px) because the page failed to constrain to the 390 px viewport. **Observed.**
- The clone’s mobile wordmark is 170 px wide versus live’s 210 px, reducing the brand block by 19%. **Observed.**
- The clone’s mobile menu is arguably cleaner (full-screen, larger touch targets) but it drops the live pattern of keeping search/cart/account visible while navigating. **Observed design difference, not a bug.**

## Console and network

### Clone

- 1 console error in the dev build: React `Received false for a non-boolean attribute compact`. The warning text resolves to `compact`; source inspection points to `components/product-detail/option-picker.tsx`, where `compact` is accepted in `OptionPickerProps` but not destructured and is spread to the DOM `div`. Observed on PDP.
- 129 console warnings, predominantly:
  - `next/image` warnings that images with `sizes="100vw"` are not rendered at full viewport width (most product/editorial images). This is a recurring warning and a potential image-optimization review item, though the repo’s style policy intentionally standardizes `sizes="100vw"`.
  - Wordmark detected as LCP without `loading="eager"`.
- Network: no failed requests and no 4xx/5xx on the clone home or PDP in the captured non-static/static request sets.

### Live

- 0 page-level console errors on the pages visited.
- Third-party warnings only: GoKwik OCC “No buttons claimed,” Meta Pixel invalid currency parameter, Swym “No Retailer Id,” Shiprocket “Universal Cookies script is already loaded.”
- One aborted Shopify monorail analytics POST (`net::ERR_ABORTED`); no failed page assets or API responses observed.
- Live loads substantially more third-party analytics/marketing code than the clone; this is expected for the production store.

## Five concrete ideas worth implementing

1. **Constrain the mobile collection page and its chip scroller.** Add the missing `min-w-0`/`w-full` constraint on the collection wrapper and chip row so the page’s `scrollWidth` equals `innerWidth` at 390 px, the grid stays 350 px wide, and the sort/filter toolbar remains on-screen. This is the highest-severity issue in the recon because it blocks browsing and sorting.
2. **Do a focused type-ramp correction.** Bring nav links to 13 px / 400 / 18, desktop “OUR PICKS” to 18 px / 400 / 23, PDP H1 to 22 px / 400 with normal tracking, and card/section headings to the live weights. The clone already matches the body font and 14 px base; the mismatch is concentrated in component weights and line-heights, so this is a small CSS-level change with a large perceived-quality payoff.
3. **Restore the live PDP conversion pattern.** Use a transparent header over the full-bleed gallery, replace colour text links with visual swatches, update variant state in place rather than navigating to a new URL for each option, and reintroduce “BUY IT NOW.” The clone already has the gallery geometry and info-column width; this is mostly presentation and state handling.
4. **Add quick view and quick add to product cards.** Match the live 28 × 28 quick-view affordance with its .25 s motion, and add a quick-add state for in-stock products. Keep the clone’s image scale if desired, but ensure the hover layer does not obscure price or wishlist controls.
5. **Bring filter and search up to live parity.** Add product-type, colour, and fabric facets with counts to the filter; use the live-style right-side sheet and .4 s easing. In search, restore larger product rows, the collections group, and the “N results found” status; remove the duplicated “SEARCH” label and widen the input to the live 392 px treatment.

Smaller follow-ups: match live’s 26 × 26 popup close target and 720/350 px popup widths; match the mobile wordmark to 210 px; keep the header and cart/search icons visible in the mobile menu; set the desktop collection row gap back to 20 px while retaining the live 24 px mobile row gap.

## Assumptions and unverified items

- **Assumption:** live INR pricing is IP-localized; clone USD is the configured default. No attempt was made to change locale or currency.
- **Assumption:** the 40-vs-13 product-card difference on `/collections/all` is a fixture/pagination difference, not a layout defect. The clone rendered 13 cards cleanly; live rendered 40 in the first viewport batch.
- **Assumption:** the live and clone product sets and ordering differ because of data fixtures and default sort (“Alphabetically, A-Z” vs “Featured”), not because either page failed to load.
- The clone dev “N” badge and HMR behavior are development-only and were not treated as storefront defects.
- No order, checkout, payment, or personal-data flow was exercised. Cart interactions were add/remove/view only; no checkout was submitted.
- No production build was run. Mobile overflow and option-navigation observations are from the local dev server; the overflow is a layout defect independent of HMR, but the timing of dev-server route transitions should not be compared to production.
