# Product Data Requirements — Working Draft

Version 1.1 · November 2026

**Internal working document.** This is a source document for review; adapt the tone, remove the
implementation appendix and confirm the open questions before presenting it to the client.

This document lists the product information needed to build the product detail pages, product
filters and product feed. It also compares the requirements with what the Polite Society storefront
currently shows, so the client conversation starts from a known baseline.

**Legend**

- **Required** — needed before launch.
- **Recommended** — strongly advised for conversion, search or legal compliance.
- **Optional** — can be added after launch.
- **System** — generated by Shopify; the client does not supply it.

Where a field is marked **per variant**, provide one value for every colour/size combination.

**What this means**

- Polite Society is a good visual reference, but it is not a complete product data model.
- The live PDP relies on description HTML for composition and care, and does not show SKU, origin,
  manufacturer, reviews or model measurements.
- The client’s list is a good content brief but needs structured fields for filters, legal
  compliance and consistent rendering.
- The biggest additions are origin/manufacturer data, structured composition/care, per-category
  size charts, curated complete-the-look products, a Size filter and a real multi-currency decision.
- Polite Society’s collection filters include Product type, Colour, Fabric and Price, but **not
  Size**. A size filter is an extension beyond the reference.

Visible live tabs on the checked PDP: `Description`, `Shipping, Exchange & Returns`, `Fabric`,
`Fit`. The live page has no visible standalone `SKU`, `Product code`, `Origin`, `Composition`,
`Reviews` or `Model height` fields; composition and care appear only inside the Description.

## Review of the current `Product Details.xlsx`

The latest workbook is a useful category skeleton, but it is not yet a product-import sheet.

**What it contains**

- Two sheets: `Meta data` and `Products`.
- `Meta data` lists 13 fields: name, price, quantity, product code, description, complete your
  look, size chart, composition, care, origin, shipping, delivery policy, exchanges and returns.
- `Products` has 58 rows covering 42 unique product names, split into menswear and womenswear
  categories: jackets, T-shirts, shirts, bottoms, skirts, shorts, dresses, bralettes, bodysuits,
  racer backs, tops and shirts.
- Only `Name`, `Colours`, `Gender` and some `quantity` cells are populated. `Price` is empty on
  every row. Description, complete-the-look, size chart, composition, care, shipping, delivery
  policy and returns are empty on every row.

**What must change before import**

1. **One row per variant, not per colour.** The sheet currently has one row per colour. Shopify
   needs one row per colour × size × any other option such as `Back`. There is no `Size` column at
   all, so the current sheet cannot create variants or a size filter.
2. **Split combined colours.** Values such as `Brown,black&white` are three colours in one cell.
   Each colour needs its own row and its own colour-family value.
3. **Add the missing commerce columns.** At minimum: size, colour family, SKU, barcode, price,
   compare-at price, inventory per variant, continue-selling policy, weight, dimensions and HS
   code.
4. **Resolve duplicate and “common” products.** The same style appears under both menswear and
   womenswear with different spacing, for example `Formal joggers (common)` and
   `Formal joggers(common)`, or `Dawg tshirt` and `Dawg tshirst`. Decide whether these are one
   unisex product or separate products, then use one consistent name and handle.
5. **Fill in the content.** Description, composition, care, origin, size chart, shipping, delivery
   and returns are currently blank. The minimum launch set in section 11 lists what is required.
6. **Add media and SEO columns.** There are no image references, alt text, video, SEO title,
   description or handle columns.
7. **Add fit and compliance data.** Model height, model size, garment measurements, manufacturer
   and importer are not represented.

The workbook is therefore a good first inventory of the range, not yet a production data schema.
The next version should be variant-level and include the controlled colour-family and fabric-family
values used by the filters.

## 2. Variants and commerce

| Field                     | Need        | Format / example                 | Notes                                                                |
| ------------------------- | ----------- | -------------------------------- | -------------------------------------------------------------------- |
| Option names              | Required    | `Colour`, `Size`, `Back`         | Use the same names across products so filters stay consistent.       |
| Colour values             | Required    | `BROWN`, `BURNT ORANGE`, `BLACK` | The names shown to the shopper.                                      |
| Colour family             | Required    | `BROWN`, `ORANGE`, `BLACK`       | The filter value. Colour names and colour families are not the same. |
| Colour swatch             | Required    | `#4E3628` or a swatch image      | One swatch per colour.                                               |
| Size values               | Required    | `XS, S, M, L, XL, XXL`           | In display order. Use `One Size` where applicable.                   |
| Other options             | Recommended | `Back: WITH LACE / WITHOUT LACE` | Any option beyond colour and size.                                   |
| SKU                       | Required    | `PS10043-XS`                     | **Per variant**, not one code per product.                           |
| Barcode / GTIN            | Optional    | `8901234567890`                  | Needed for some marketplaces and stock systems.                      |
| Price                     | Required    | `158.00 USD`                     | Per variant and per market if prices differ.                         |
| Compare-at price          | Optional    | `198.00 USD`                     | Only if the product is genuinely on sale.                            |
| Cost per item             | Optional    | `62.00 USD`                      | Internal margin data; never shown to the shopper.                    |
| Taxable                   | Required    | `Yes`                            | Whether tax applies.                                                 |
| Inventory quantity        | Required    | `12` or `Do not track`           | Per variant. If not tracked, say so explicitly.                      |
| Continue selling when out | Required    | `No`                             | Whether backorders are allowed.                                      |
| Purchase limit            | Optional    | `Max 3 per order`                | Any per-order or per-customer limit.                                 |
| Weight                    | Recommended | `450 g`                          | Per variant; used for shipping.                                      |
| Packed dimensions         | Recommended | `30 × 24 × 4 cm`                 | Per variant or per product.                                          |
| HS code                   | Recommended | `6204.42`                        | For international shipping and customs.                              |
| Country of origin         | Required    | `India`                          | Per product or per variant if they differ.                           |
| Variant image mapping     | Recommended | `BROWN / XS → image 1`           | Which images belong to which colour.                                 |
| Variant availability      | System      | Generated by Shopify             | From inventory and the “continue selling” setting.                   |

## 5. Fit and sizing

| Field                | Need        | Format / example                          | Notes                                       |
| -------------------- | ----------- | ----------------------------------------- | ------------------------------------------- |
| Fit type             | Required    | `True to size`, `Relaxed`, `Bodycon`      | The shopper’s first fit signal.             |
| Model height         | Recommended | `5 ft 9 in / 175 cm`                      | State the unit.                             |
| Model size worn      | Recommended | `XS`                                      | The size shown in the images.               |
| Model measurements   | Optional    | `Bust 32 in, waist 25 in, hip 35 in`      | Helps shoppers compare.                     |
| Stretch              | Recommended | `Slight stretch`                          | None, slight or generous.                   |
| Lining               | Recommended | `Fully lined`                             | Helps with opacity and comfort.             |
| Garment measurements | Required    | `Bust 34 in, waist 27 in, length 22 in`   | Flat measurements per size. State the unit. |
| Size chart category  | Required    | `Tops`, `Dresses`, `Bottoms`, `Outerwear` | Assign every product to one category.       |
| Size conversions     | Required    | `US 4 / UK 8 / EU 36`                     | For every size offered.                     |
| Body measurements    | Required    | `Bust, waist, hip`                        | Used by the size guide.                     |
| Measurement units    | Required    | `cm and in`                               | Provide both where possible.                |
| Size guide notes     | Optional    | `This style runs small; size up.`         | Product-specific fit advice.                |

**Size chart rule:** one chart per category is enough. Product-specific measurements are only
needed when the silhouette differs from the category chart.

## 10. Filter data

Filters only work when the values are structured and consistent. Please provide the following
controlled vocabularies.

| Filter       | Source         | Allowed values / example                                                                                |
| ------------ | -------------- | ------------------------------------------------------------------------------------------------------- |
| Product type | Product type   | `DRESS`, `CORSETS`, `TOPS`, `TROUSERS`, `SHIRTS`, `SKIRT`                                               |
| Colour       | Colour family  | `BLACK`, `WHITE`, `BROWN`, `BEIGE`, `RED`, `PINK`, `BLUE`, `GREEN`, `GREY`, `ORANGE`, `PURPLE`, `DENIM` |
| Size         | Variant option | `XS`, `S`, `M`, `L`, `XL`, `XXL`, `One Size`                                                            |
| Fabric       | Fabric family  | `COTTON`, `SILK`, `VISCOSE`, `NYLON`, `POLYESTER`, `DENIM`, `LINEN`, `WOOL`, `LACE`, `SATIN`            |
| Fit          | Fit family     | `BODYCON`, `RELAXED`, `OVERSIZED`, `TRUE TO SIZE`                                                       |
| Occasion     | Occasion       | `DAY`, `EVENING`, `WORK`, `WEDDING`, `RESORT`                                                           |
| Availability | Inventory      | `In stock`, `Out of stock`                                                                              |

**Important:** the colour family is not always the colour name. `BURNT ORANGE` may belong to the
`ORANGE` family; `TUXEDO BLACK` may belong to `BLACK`. Please provide the mapping.

The filter vocabulary must be finalised before the client fills in products, otherwise filters
will show duplicates or empty values.

## 11. Minimum launch set

At minimum, provide the following for every product:

### Per product

- Name, product type, brand, URL handle
- Short description, long description
- SEO title and description
- Collections
- Main composition, care, country of origin
- Fit type
- Size-chart category
- Shipping/returns exceptions, if any
- At least 3 images per colour with alt text
- Complete-the-look products, if used

### Per variant

- Colour name and colour family
- Size
- SKU
- Price
- Inventory or “do not track”
- Continue-selling policy
- Weight and dimensions, if shipping internationally

### Per category

- Size chart with body and garment measurements
- Size conversions
- Fit guidance
- Care guidance for the fabric family

### Per store

- Shipping policy
- Delivery estimates
- Returns and exchanges policy
- Duties/taxes policy
- Legal and compliance requirements by market
- Brand tone and description style

## 12. Submission format

Please supply:

1. **One spreadsheet row per variant**, with product-level fields repeated or linked by handle.
2. **One image folder per product**, named by handle and colour.
3. **One size-chart sheet per category**.
4. **One store-policy document** covering shipping, returns and duties.
5. **A colour-family mapping** for every colour name.
6. **A fabric-family mapping** for every fabric composition.

Suggested spreadsheet columns:

```text
handle | title | product_type | vendor | collections | tags | seo_title | seo_description
colour_name | colour_family | colour_hex | size | other_option | sku | barcode

short_description | long_description | styling_notes

```

## 14. Please do not

- Put price, SKU or inventory inside the description.
- Put composition, care, fit or size charts only inside the description.
- Use free text for colour families or fabric families.
- Use different colour names for the same colour across products.
- Change handles after launch without a redirect.
- Supply images without alt text or usage rights.
- Assume “complete the look” is automatic; it is curated.
